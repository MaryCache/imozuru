# 海外言語での探索ガイド

英語と日本語だけでは、特定の地域・言語圏で一次研究や実践が先に進んでいる分野に届かないことがある。題材に応じて原産言語や主要言語圏を広げ、現地語の一次情報までたどるための手順をここにまとめる。

## 1. 掘る言語圏を選ぶ（0周目・証拠で決める）

媒体と同じく、掘る言語圏も親の勘だけで決めつけず、0周目の証拠から選ぶ。

1. 入口で原産言語が明らかな題材: 特定の国・文化・製品・技法に紐づく問い（例: 大陸塗り→中国語・韓国語、ドイツ規格→ドイツ語）は、0周目の2本のうち1本を最初からその言語に割り当てる。
2. 入口で分からない題材: 0周目の論点1（「この分野の知見はどこに集まっているか」）に**言語圏の特定**を含め、次の証拠を見て日英以外の有力な言語圏を拾う。
   - 多言語版 Wikipedia: 英語版・日本語版から他言語版へのリンクを見て、本文や脚注（References）が特に厚い言語版があるか確かめる。
   - 著者・研究機関・引用元の分布: `chain.py`（OpenAlex）や 0周目の検索結果で、繰り返し名前が挙がる著者・研究室の地域や、引用されている原典の言語を見る。
3. 1周目以降の割り当て: 検索役の同時起動は2本までの境界を守り、証拠で浮かび上がった言語圏があれば、周を分けて1本をその言語の検索役（現地用語を拾って引き直す）に割り当てる。
4. 飽和の数え方: 飽和（7割）を数える対象は同じ問いを違う探し方で探した検索役どうしに限る。別の言語圏へ広げた周で新しい一次資料がまとまって出た場合は、言語圏ごとの未開拓としてそのまま掘る。

## 2. 直訳を避け、現地用語を拾う

日本語や英語の検索語をそのまま直訳しても、現地の界隈や学会で使われている呼び方と外れることが多い。次の順で **現地用語（native terminology）** を拾ってから引き直す。

1. 多言語版 Wikipedia の言語リンク: 英語版や日本語版の記事から対象言語版へ切り替え、記事題名・見出し・References（脚注）にある現地語と定番資料を拾う。
2. 論文・公式仕様のキーワード: OpenAlex や原著の抄録にある現地語のキーワード・タグを拾う。
3. `map.md` に言語つきで記録: `## 用語` に `<現地用語>（<言語>・<日本語の呼び方>）— <出典>` の形で残し、次の周の「言葉で引き直す」に使う。

## 3. 言語圏ごとの一次情報・媒体の目安

媒体は固定の一覧から選ばず0周目で探すのが原則だが、見当がまったくつかないときの出発点として次を目安にする。

| 言語圏 | `fetch.py` で取得しやすい一次媒体・リポジトリ | 壁になりやすい媒体（ブラウザ取得・`ingest.py` 前提） |
|---|---|---|
| 中国語（簡体・繁体） | 站酷（Zcool）、網易（163）、大学出版社の公開 PDF、GitHub 個人ブログ、arXiv（中華圏著者）、CLIP STUDIO TIPS 繁体字、GCORES | 知乎（403 / JS 描画）、CSDN（HTTP 521）、萌娘百科（JS 描画）、小紅書（ログイン必須）、CNKI 本文（有料） |
| 韓国語 | YouTube（韓国語講義の字幕）、Paintingstack、CLIP STUDIO KR、KCI、大学リポジトリ、個人サイト（하루소식 等） | Tistory（403）、Postype（ボット対策の空応答）、Naver 有料/会員記事 |
| ドイツ語 | 大学リポジトリ・音楽大学公開教材（OpenMusic Academy 等）、Wikisource / Wikibooks、archive.org（`_djvu.txt`）、heise online、個人ブログ | Heidelberg ArtDok（Anubis ボット確認）、uni-weimar wiki 等の一部 403、有料専門誌 |
| フランス語 | HAL（`hal.science/<id>/document` の PDF 直取り・`fetch.py` が自動補完）、Persée、archive.org（`_djvu.txt`）、技術ブログ | OpenEdition（Anubis ボット確認）、HAL の通常記録ページ、有料学術誌 |
| スペイン語・ポルトガル語 | SciELO、Redalyc、Dialnet、大学・研究機関の公開資料 | 会員制・有料媒体 |
| ロシア語 | CyberLeninka（OA 論文）、Habr、個人ブログ | 一部の露大学ホスト（地域遮断・TCP タイムアウト）、ログイン必須フォーラム |
| アラビア語・その他 | 各言語版 Wikipedia の References、大学・公的機関の一次発表、YouTube 字幕 | ログイン必須 SNS |

※ 2026-11-26 の実測（中・韓・独・仏・露・ウクライナ語の計 197 本試行）に基づく。海外リポジトリは通常検索で出にくいため、`site:hal.science` や `site:cyberleninka.ru` のドメイン指定検索が有効。また `archive.org` は `/details/<id>`（書誌ページ）ではなく `/download/<id>/<id>_djvu.txt` の本文 URL を渡す。ログイン必須の SNS や有料データベースは境界どおり回避せず、ログイン不要の別置き場を探すか、URL を並べてユーザーへ渡す。

## 4. 海外言語の取得・照合・表示のコツ

- 文字コード・IDN: `fetch.py` は UTF-8・宣言 charset・HTML の `lang` ヒントに基づく主要コードページ（GB18030 / Big5 / CP949 / CP1251 / CP1252 / CP1256 等）へ自動でフォールバックする。国際化ドメイン名（IDN）も Punycode 変換したうえで SSRF 検査と取得を行う。
- PDF の短さ下限と OCR: 日本語・中国語・韓国語（ハングル）が3割を超える PDF は 1,000 字下限で判定される。文字層の無いスキャン PDF で確信度不足の `FAIL` が出たら、言語に合わせて `IMOZURU_OCR_LANG` を指定して取り直す（例: `IMOZURU_OCR_LANG=chi_sim+eng`、`kor+eng`、`deu+eng`、`fra+eng`、`rus+eng`、`ara+eng`）。
- YouTube 字幕: `fetch.py` は日本語・英語の手動字幕→動画の元言語（`zh-Hans` などサブタグつきの完全なタグ）の手動字幕→元言語の自動字幕の順で取得する。特定の言語を優先したいときは `IMOZURU_YT_LANGS=zh-Hans,en` のように環境変数で指定でき、字幕が複数あればその並び順で選ぶ（`all`・`live_chat` は指定不可）。
- 引用照合（`report.py` / `digest.py`）: 照合前に Unicode の NFC 正規化を行うため、仏・独・西・韓などの合成/分解差で照合に失敗しにくい。引用は翻訳せず原文のまま切り出す。
- 抜き書きの表示（`extracts.json`）: 日本語以外の原文には `ja` に日本語訳を添える。必要なら `"lang"`（例: `"zh"`, `"ko"`, `"de"`, `"fr"`, `"ru"`, `"ar"`）を付けると、`report.html` のフォント選択やアラビア語・ヘブライ語の右横書き（`dir="auto"`）が正しく適用される（省略時は文字種から自動推定される）。
