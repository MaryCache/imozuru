# 抜き書きと詳細レポートの仕様

調査を止める判定を出したあとに作成する。

## 抜き書きのページ（report.py）

原文を何十本も保存しただけでは読まれない（英語の PDF や1時間の字幕のまま）。かといって要約すると、早すぎる結論を招く。そのため調査を止めたら、抜き書き（Ellis の extracting）でページを作り、それを最初に渡す。

1. `<topic_dir>/extracts.json` を書く。
   - 調査の論点ごとに節を立て、原文から**そのまま切り出した文**を並べる（ファイル・行・必要なら `end`）。
   - 日本語以外の原文（英語・中国語・韓国語・欧州言語など）には `ja` に訳を添える（訳だと分かる印がページに付く）。必要なら `"lang"`（例: `"zh"`, `"ko"`, `"de"`, `"fr"`, `"ar"`）を添えるとフォント選択や右横書き（`dir="auto"`）が正確に当たる（省略時は文字種から自動推定される）。印（〔本人〕自動字幕 など）は `mark` に書く。
   - 元のページへのリンクは `map.md` の「原文（sources/）」の表にある「元の URL」から、表に無ければ取得の記録（`fetch-log.jsonl`）から自動で付く（http(s) の完全な URL だけ）。どちらにも無い原文に付けたいときだけ `url` に書く。
   - 2段組の PDF のように左右の段が1行に混ざる所は、抜き書きを「…」で区切ると区切りごとに順に照合される（省いたことはページにも「…」で見える）。
   - 負号・箇条書きの扱い: 数で始まる所を写すとき、原文でその直前に負号やダッシュ（`-`・`−`・`－`・`–`）があれば、その記号ごと写す。数で始まる箇条書きの項目も `"- "` ごと写す（負号と見分けられないため、落とすと照合で止まる）。
   - 食い違いは `disagreements` に並べるだけで、どれが正しいかは書かない。届かなかったものは `unreached` に書く。
   - 形の手本は `scripts/report.py` の冒頭（リポジトリ同梱の `examples/demo/extracts.json` が手元にある場合はそちらも参照可能。`?` は省いてよい）。

   ```text
   {"title", "question", "stopped",
    "claims": [{"claim", "status": "根拠あり|一部のみ|根拠なし", "note"?,
                "quotes": [{"file", "line", "end"?, "text", "ja"?, "lang"?, "mark"?, "url"?}]}],
    "disagreements"?: [{"topic", "quotes": [{"file", "line", "text", "who", ...}]}],
    "unreached"?: ["..."]}
   ```

2. `scripts/report.py <topic_dir>` を回す。
   - **抜き書きが原文の指定行（前後2行を含む範囲・空白等を正規化）に在るかを機械で照合し**、1つでも合わなければ HTML を作らずに止まる（言い換えが紛れ込むのを防ぐ）。合えば `report.html` ができる。各抜き書きは「前後を読む」で原文の前後を開ける。
3. エージェントが書いてよいのは、見出し・状態（根拠あり／一部のみ／根拠なし）・1行の注記・訳だけ。注記にも結論や評価は書かない（「順番は記事ごとに違う」はよい、「この順が正しい」は書かない）。注記は誰が何をどうしたかが分かる文で書く。
4. 自動字幕の誤変換は直さずにそのまま切り出す（直すと言い換えになる）。印に「自動字幕」と書けば、読む人が動画で確かめられる。

## 詳細レポート（digest.py）

抜き書きは原文を並べるだけなので、その分野を知らない人にはどれから読めばよいかも言葉の意味も分からない。詳細レポートは調べたドメインの知識を読み手の負担が少ない形で渡し、同時に何を探して何が出たかを全部見せる。調査を止めたあとに作る（要約を止めていたのは早すぎる結論を避けるためで、止めたあとなら書いてよい）。

2つの層に分ける。

- 解説: エージェントが `digest.json` に書く。読み手の水準ごとに3編を分け、水準ごとに書く中身を変える（同じ中身の言葉だけを易しくしない）。
  - Lv1（前提知識が無い人向け）: 何が起きているか。要旨（3〜5文）、日常の言葉による用語の定義、論点ごとの解説を書く。
  - Lv2（近い分野を知っている人向け）: 仕組み。数式・数値・近い分野の用語で、教科書の水準まで書く。
  - Lv3（この分野を専門にする人向け）: 仕組みは知っている前提で、通説のどこが修正されたか、何が未決着か、どの手法と数値で示されたか、出典どうしの食い違いを書く。Lv2 と同じ文を置かない。
  - 3編に共通で、人物と媒体（誰がどこで発信しているか）と、未解決の点（原文が付かなかった論点・届かなかった資料）を書く。
- 記録: `queries.jsonl` と `fetch-log.jsonl` から機械で組む。周ごとに、検索語・誰が探したか・ヒットの全件を並べ、それぞれに〔保存〕〔取得失敗〕〔未取得〕を付ける。空振りの検索語も載る。検索で挙がっていない取得（記事の中のリンクをたどったもの）も別に並ぶ。エージェントはこの層を書かない。

手順は次のとおり。

1. `<topic_dir>/digest.json` を書く。**解説の1文ごとに、根拠として原文からそのまま切り出した引用を1つ以上付ける**（ファイル・行・必要なら `end`。抜き書きと同じ形）。根拠の無い文は書かない。編をまたいで同じ引用を使ってよい。

   ```text
   {"title", "question", "stopped",
    "claims": [{"claim", "status": "根拠あり|一部のみ|根拠なし"}],
    "levels": {"lv1": 編, "lv2": 編, "lv3": 編},
    "people_places": [文], "unresolved": ["..."]}
   編 = {"summary": [文], "terms": [{"term", "sentences": [文]}], "answers": [{"claim", "sentences": [文]}],
         "quiz": [{"q", "answer": [文]}]}
   文 = {"text", "quotes": [{"file", "line", "end"?, "text"}]}
   ```

2. `scripts/digest.py <topic_dir>` を回す。**全部の文の引用を抜き書きと同じ方法で原文と照合し**、根拠の無い文や原文に無い引用が1つでもあれば HTML を作らずに止まる。通れば `digest.html` ができる。文の後ろの番号から根拠の引用と原文の前後を開ける。
3. `claims` には `map.md` の調査の論点と、原文が付いたかを書く。ページの冒頭には「調べたこと・調査を区切った理由・調査の論点」の3つだけを置く。
4. 各編の末尾に、確かめる問いを2〜3問書く（`quiz`）。答えは解説の文と同じく原文の引用で裏づける。読み返すより自分をテストするほうが定着する（Dunlosky ら 2013）。問いは、その編の読み手が答えられる水準で書く。
5. ページは編を1つずつ切り替えて見せ、文を押すとその文の下に根拠の引用が開く。記録の層はどのサイトを見て何件保存・失敗したかの集計を先に置き、検索語ごとの全件は周ごとに畳む。設計の根拠は `~/research/cognitive-load-dataviz/`（分割注意・熟達化の逆転・概観から詳細へ・来歴の表示）。
6. 解説の文は誰が何をどうしたかが分かる文で書く。照合で確かめられるのは「引用が原文に在ること」までで、「文が引用の言うとおりか」は確かめられない。引用が言っていないことを文に足さない。
