# 見張る（watch モード）

調べたあとの `map.md` の「媒体」を新着を追う先にする（Ellis の monitoring）。「〇〇の新着見て」「今週の〇〇まとめて」「/imozuru watch <話題>」で入る。**ユーザーが頼んだときだけ回す**。定期的に自動で回すかは何回か思いどおりに動いてから決める。

1. `map.md` があるか見る。`~/research/<話題>/map.md` が無いとき（いきなり「React の新着」と頼まれたとき）は、2つの入り方がある。
   - 急ぐとき（既定）: 定番の場所（公式のブログ・GitHub の releases、Qiita のタグ、Zenn のトピック、名前の知れた個人ブログ）をそのまま足して先に見張る。`map.md` は問い・媒体・人だけで作り、あとで書き足す。React の試行では 0周目の検索役2本に約2分かかり、結果は定番を直接足したのとほぼ同じだった。
   - 場所の見当がつかない分野: `SKILL.md` の「1. map.md を作る（0周目）」だけ回して媒体を作ってから見張る。

2. 見張る先を足す。`map.md` の「媒体」と「人」から、新着を出す場所を選んで `scripts/watch.py add <topic_dir> <url>` で足す。
   - 足せる先: Qiita のタグ・ユーザー、Zenn のトピック・ユーザー、note のユーザー、Reddit、YouTube のチャンネル、RSS を出しているブログ、arXiv の検索（`http://export.arxiv.org/api/query?search_query=...&sortBy=submittedDate&sortOrder=descending`）。
   - X と pixiv は RSS を出していないため追加できず、見張れないことを返事に書く。
   - RSS があるかは検索役の言葉ではなく `watch.py add` で決める。検索役は RSS の URL を推測で書くことがあり、「無い」と報告した `react.dev` のフィードも実際は取得できた。逆に「更新が止まっている」という検索役の言葉は、`check` の「最新の1件」で確かめる。

3. 新着を引く。`scripts/watch.py check <topic_dir>` で前回から新しいものを出す（初回のフィードは直近14日・`--days` で変える）。結果は `watch/<日付-時刻>.md` に残る（同じ日に何度回しても前の結果は消えない）。
   - 新着の無い場所にも期間に関係なく最新の1件が出る。公式の大きな出来事が期間より前でも見える。
   - 期間を広げて出し直すときは `--fresh`。初回の期間より前の記事も「見た」と記録されるので、記録を無視して期間だけで選び直す。

4. 渡す。新着の一覧を見せる。1件ごとに題名・日付・場所と、フィードに入っている原文の冒頭1行（`>` の引用）を並べる。
   - **エージェントの要約や点数は付けない**（原文の冒頭なら書き手の言葉のまま選ぶ手がかりになる）。
   - ユーザーが選んだもの、または調査の論点に関わると見たものだけ `fetch.py` で原文を保存し、原文の表に印つきで足す。
   - 件数が多いとき（目安20件超）は、依頼に合わせて種類で絞って見せてよい（「個人ブログと海外も」なら Qiita・Zenn の数を減らす）。絞ったことと、全件のファイルの場所を書く。絞るのは選び方だけで、要約はしない。
   - 新着の無かった場所の「最新の1件」は一覧の最後に短く添える。

5. 新着の中に、`map.md` に無い人・媒体・用語が繰り返し出ていたら、`map.md` の「次の手がかり」に足し、見張る先に加えるかをユーザーに聞く。見張りから、もう一度調べる流れへ戻るきっかけになる。
